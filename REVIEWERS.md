# Notes for Mozilla add-on reviewers

**Foxy Jumpscare** — a joke extension that shows a rare fullscreen jumpscare
overlay while browsing.

No JavaScript, HTML or CSS in the submitted package is minified, bundled,
transpiled, or obfuscated. Every script ships exactly as written here, with its
comments intact. The build step is a file copy plus three generated artifacts,
listed below.

---

## Building

Requires Node 24 / npm 11.

```
npm install
npm run build          # -> dist/firefox
```

`dist/firefox` is the contents of the submitted package.

The build needs two media inputs that are not in this archive, for the licensing
reason in "Generated files" below: `assets/foxy.webm` and the icons. Both are in
the submitted package. To reproduce it exactly, copy them back first:

```
mkdir assets
cp <submitted-package>/foxy.webm assets/foxy.webm
cp <submitted-package>/icons/*.png extension/src/icons/
npm install
npm run build
npm run package        # -> dist/packages/foxy-jumpscare-firefox-v0.1.4.zip
```

`npm run build` regenerates the icons only if `extension/src/icons/` is empty,
so the copies above survive it. On a checkout with no icons at all it draws the
procedural placeholder described below instead.

Packaging is deterministic — fixed archive timestamps, no random input — so
this produces a **byte-identical** zip to the one submitted. Verify with
`sha256sum`.

## Generated files, and what generates them

| In the package | Generated by | Notes |
|---|---|---|
| `manifest.json` | `tools/build-extension.mjs` | Merges `extension/manifest.base.json` with the browser-specific `background` and `browser_specific_settings` blocks. Chrome and Firefox disagree on how an MV3 background is declared, so one base manifest produces two. |
| `icons/*.png` | `tools/make-icons.mjs` | ffmpeg crops a still render to the head and resizes it to each size. A media asset, not code. Without that still, the same script draws original artwork procedurally with node's zlib — no image library, no input image. |
| `foxy.webm` | `tools/build-assets.mjs` | ffmpeg keys a greenscreen source video to VP9 with alpha. A media asset, not code. |

Everything else under `extension/src/` is copied verbatim.

Neither media source is included in this archive. Both are third-party material
we do not have redistribution rights to, so shipping them in a source archive
would make the problem worse rather than better. The exact ffmpeg invocations
that produce the outputs are in `tools/build-assets.mjs` and
`tools/make-icons.mjs`, and both outputs are in the submitted package for
inspection.

## How it works

- `background.js` — an event-page background script. Drives a once-per-minute
  `chrome.alarms` tick, and credits elapsed time against a countdown only while
  the browser is focused and the user is not idle.
- `lib/roll.mjs` — the odds. Samples the wait once from a geometric
  distribution rather than rolling every second, because a 1 Hz timer in a
  background script is throttled and would silently bias the odds. Pure
  arithmetic, no browser APIs.
- `lib/fire.mjs` — when the countdown reaches zero, injects the overlay into
  every open tab it is permitted to touch.
- `lib/inject.mjs` — the injected function. Appends one `<iframe>` pointing at
  the extension's own `overlay.html` and nothing else.
- `overlay.html` / `overlay.js` — plays the video, then removes itself. There
  is an independent failsafe timer that tears the overlay down at video
  duration + 1.5s regardless of media state, so a video that fails to decode
  cannot leave the overlay on screen.
- `panel.html` / `panel.js` — the toolbar popup and options page.

### Why an iframe rather than injected media

The overlay is an extension-origin iframe, not injected `<video>`. Three
reasons, all load-bearing:

1. Page CSP blocks injected media on sites like GitHub.
2. Page autoplay policy silently kills content-script audio.
3. Host page CSS leaks into injected nodes.

### On `<all_urls>`

Required only so the overlay can be drawn on whatever page the user is on when
it fires. The extension does not read, collect, or transmit page content — it
appends an element and removes it about a second later.

There are **no network requests of any kind**, no analytics, no telemetry, no
remote code, and no `eval`. Stored data is limited to the user's own settings
and the countdown, in `chrome.storage.local`. This is declared in the manifest
as `data_collection_permissions: { required: ["none"] }`.

### Content warning

The extension deliberately plays sudden loud audio. This is disclosed in the
store description and in the extension's own UI.
